Гайд по стартовому разделу roadmap Neetcode. Идейно он самый простой: за всеми задачами стоит одна структура данных — hash-таблица — и один приём её применения: за один проход построить структуру, которая отвечает про уже просмотренную часть входа за $O(1)$ на вопросы «видели ли?», «где?», «сколько раз?». Наивные решения тех же задач перебирают пары за $O(n^2)$; вся суть раздела — обменять память на время. Разберём устройство самой таблицы, универсальный приём и его параметризации и один частный случай — массив вместо таблицы; конкретные задачи сведены в карту в конце.

Как узнать раздел по условию: вход не отсортирован и сортировать его не обязательно, а спрашивают про существование, дубликаты, частоты, пары с заданной суммой или группировку «одинаковых» объектов. Если массив отсортирован — сначала думаем про [[two-pointers]] и [[binary-search]]; если ищем подмассив или подстроку с условием — это [[sliding-window]]. Четыре задачи, которые Neetcode кладёт в этот же узел, к хэшированию не относятся, и здесь мы их не рассматриваем: Product of Array Except Self, Range Sum Query — Immutable и Find Pivot Index — это prefix-агрегаты, Encode and Decode Strings — сериализация с префиксом длины. И одна оговорка сразу, чтобы не повторять её в каждом разделе: всё здесь стоит $O(n)$ времени и $O(n)$ памяти — это и есть цена обмена; исключения оговорены на месте.

## Hash-таблица за пять минут

Устройство: массив из $m$ bucket-ов и hash-функция, превращающая ключ в индекс, $\text{bucket} = h(\text{key}) \bmod m$. Вставка и поиск — вычислить индекс и заглянуть ровно в один bucket, никакого сканирования. Разные ключи могут попасть в один bucket — это коллизия, тогда внутри bucket-а живёт короткая цепочка; пока элементов не сильно больше, чем bucket-ов, цепочки в среднем длины $O(1)$. Когда таблица заполняется, она пересоздаётся вдвое больше с перекладыванием всех элементов — дорого, но настолько редко, что амортизированно вставка остаётся $O(1)$.

Из устройства следуют три вещи, которые стоит уметь проговаривать на интервью. Первое: `insert`, `lookup`, `delete` работают за $O(1)$ *average*; worst case — $O(n)$, если все ключи столпились в одном bucket-е. Второе: ключ обязан быть hashable, то есть неизменяемым — если ключ мутирует после вставки, его хэш меняется, и найти его в таблице больше нельзя; в Python поэтому ключом может быть `tuple`, но не `list`. Третье: элементы лежат в порядке, продиктованном hash-функцией, то есть ни в каком; если от структуры нужен порядок — это к сортировке, [[heap]] или BST из [[trees]].

Python даёт четыре обёртки над одной и той же таблицей: `set` (только ключи), `dict` (ключ $\to$ значение), `collections.Counter` (частоты с готовой арифметикой) и `collections.defaultdict` (значение по умолчанию — удобно для группировок).

## Один приём: проход + память об увиденном

Скелет почти любого решения в разделе:

```python
seen = ...                  # everything we know about the scanned part
for x in data:
    ...                     # 1. ask seen a question about the past
    ...                     # 2. register x in seen
```

Наивное решение для каждого элемента заново сканирует остальной массив — отсюда $O(n^2)$. Мы вместо сканирования спрашиваем структуру, и вопрос стоит $O(1)$.

> [!important]
> Задачи на hash-таблицы отличаются друг от друга только ответами на два вопроса: **что взять ключом** и **что положить в значение**. Сам цикл всегда один и тот же.

### Значение не нужно: set

Вопрос — «видели ли мы это?»: дубликаты, принадлежность, повтор состояния.

```python
def has_duplicate(nums: list[int]) -> bool:
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False
```

У шаблона две степени свободы, которые сильно расширяют его применимость. Ключ может быть составным: в Valid Sudoku кладём в один set кортежи $(d, \text{row})$, $(d, \text{col})$, $(d, \text{box})$ — и три ограничения проверяются одним проходом. А «элементом» может быть не число из массива, а состояние процесса: Happy Number крутит итерацию и ждёт, когда состояние повторится, — повтор означает цикл.

Более тонкое применение — Longest Consecutive Sequence: найти длиннейшую серию подряд идущих чисел за $O(n)$, то есть без сортировки. Кладём всё в set и раскручиваем каждую цепочку строго из её начала: $x$ — начало серии, если $x - 1$ в set нет.

```python
def longest_consecutive(nums: list[int]) -> int:
    values = set(nums)
    best = 0
    for x in values:
        if x - 1 in values:      # not a sequence start, skip
            continue
        length = 1
        while x + length in values:
            length += 1
        best = max(best, length)
    return best
```

С виду тут вложенный цикл, но внутренний `while` посещает каждый элемент множества ровно один раз — внутри его собственной серии, начатой с левого конца, — поэтому суммарно все запуски `while` делают не больше $n$ шагов, и это $O(n)$, а не $O(n^2)$. Такой способ считать — работу учитываем по элементам, а не по итерациям внешнего цикла — называется амортизированным анализом и пригодится далеко за пределами раздела, например в monotonic stack из [[stack]].

### Значение — индекс или счётчик: map

Как только вопрос усложняется до «где видели?» или «сколько раз видели?», set превращается в map.

«Где» — это поиск пары-дополнения. Two Sum: вместо перебора всех пар для каждого $x$ спрашиваем, встречался ли уже $\text{target} - x$. Фокус в том, что дополнение вычислимо заранее — значит, его можно не искать перебором, а спросить lookup-ом.

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}    # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
```

«Сколько раз» — это счётчик частот, и в Python он готовый: Valid Anagram — буквально `Counter(s) == Counter(t)`, Ransom Note — проверка, что один счётчик покрывает другой. Счётчики частот — рабочая лошадка и соседних разделов, от [[sliding-window]] до [[heap]].

### Ключ — каноническая форма: группировка

«Сгруппируйте одинаковые», где одинаковость — не равенство, а эквивалентность: анаграммы, строки, совпадающие с точностью до сдвига алфавита, точки на одной прямой. Hash-таблица сгруппирует за нас, если придумать **каноническую форму** — функцию, которая всем членам одного класса эквивалентности даёт один и тот же ключ. Для анаграмм годятся две: отсортированная строка ($O(k \log k)$ на слово длины $k$) и кортеж из 26 частот ($O(k)$); кортеж, а не список — потому что ключ обязан быть hashable.

```python
def group_anagrams(strs: list[str]) -> list[list[str]]:
    groups: dict[tuple, list[str]] = defaultdict(list)
    for s in strs:
        count = [0] * 26             # canonical key: letter frequencies
        for ch in s:
            count[ord(ch) - ord("a")] += 1
        groups[tuple(count)].append(s)
    return list(groups.values())
```

Весь интеллектуальный труд в задачах на группировку — придумать канонизацию; дальше `defaultdict(list)` делает всё сам. Сложность $O(n \cdot k)$ — единственное место раздела, где в ответе живёт длина слова.

### Ключ — префиксная сумма: Two Sum на подмассивах

Приём дотягивается и до задач про подмассивы. Subarray Sum Equals K: сколько подмассивов имеют сумму ровно $k$. Заведём префиксные суммы — накопленные суммы первых элементов, $\text{prefix}[i] = \sum_{j < i} a_j$. Сумма подмассива $(l, r]$ — это разность $\text{prefix}[r] - \text{prefix}[l]$, а значит, подмассивов с суммой $k$, кончающихся в позиции $r$, ровно столько, сколько раз левее встречался префикс $\text{prefix}[r] - k$. Узнаёте? Это Two Sum: тот же поиск дополнения lookup-ом, только ключом стал накопленный агрегат, а значением — счётчик уже встреченных префиксов.

```python
def subarray_sum(nums: list[int], k: int) -> int:
    seen = {0: 1}                    # empty prefix
    prefix = result = 0
    for x in nums:
        prefix += x
        result += seen.get(prefix - k, 0)
        seen[prefix] = seen.get(prefix, 0) + 1
    return result
```

В отличие от [[sliding-window]], подход не требует неотрицательности элементов: окну нужна монотонность суммы при расширении, а префиксам с lookup-ом она безразлична.

## Массив вместо hash-таблицы

Когда ключи — целые числа из небольшого известного диапазона, hash-таблица избыточна: массив, индексированный ключом, — та же таблица, только hash-функция тождественная и коллизий нет по построению. Счётчик `[0] * 26` в `group_anagrams` выше — ровно этот случай.

Тот же взгляд даёт линейную замену сортировке. В Top K Frequent Elements частота любого элемента лежит в диапазоне $[1, n]$ — значит, раскладываем элементы по «bucket-ам частоты» и читаем bucket-ы с конца, пока не наберём $k$. Ни полная сортировка за $O(n \log n)$, ни [[heap]] за $O(n \log k)$ не нужны.

```python
def top_k_frequent(nums: list[int], k: int) -> list[int]:
    count = Counter(nums)
    buckets: list[list[int]] = [[] for _ in range(len(nums) + 1)]
    for value, freq in count.items():
        buckets[freq].append(value)      # index == frequency
    result: list[int] = []
    for freq in range(len(nums), 0, -1):
        result.extend(buckets[freq])
        if len(result) >= k:
            return result[:k]
    return result
```

Общий принцип: ключ сортировки — целое из известного диапазона $\Rightarrow$ counting/bucket sort за $O(n)$. Sort Colors — тот же принцип в вырожденном виде: три значения, три счётчика.

## Карта задач

Задачи раздела, разложенные по идеям выше; колонка «деталь» — то единственное, чем задача отличается от голого шаблона.

| Задача | Идея | Деталь |
| --- | --- | --- |
| Contains Duplicate | set | шаблон как есть |
| Valid Sudoku | set | составной ключ $(d, \text{row})$ / $(d, \text{col})$ / $(d, \text{box})$ |
| Happy Number | set | «элемент» — состояние итерации, повтор = цикл |
| Longest Consecutive Sequence | set | старт цепочки: $x - 1$ отсутствует; амортизированный счёт |
| Two Sum | map: значение = индекс | lookup дополнения $\text{target} - x$ |
| Valid Anagram | map: счётчик | `Counter(s) == Counter(t)` |
| Ransom Note | map: счётчик | один счётчик покрывает другой |
| Majority Element | map: счётчик | бонус: Boyer–Moore даёт $O(1)$ памяти |
| Group Anagrams | канонический ключ | кортеж из 26 частот |
| Group Shifted Strings | канонический ключ | разности соседних букв $\bmod 26$ |
| Subarray Sum Equals K | map: ключ = префиксная сумма | Two Sum по префиксам |
| Top K Frequent Elements | массив вместо таблицы | bucket-ы по частоте |
| Sort Characters By Frequency | массив вместо таблицы | те же bucket-ы, читаем в строку |
| Sort Colors | массив вместо таблицы | три счётчика (или Dutch flag из [[two-pointers]]) |

Четырнадцать задач — и по существу одна идея с параметрами: hash-таблица, в которой от задачи к задаче меняются только ключ и значение, плюс её частный случай — массив для маленьких целых ключей. Главный навык раздела — распознать, что взять ключом и что положить в значение, — дальше задача сведена к шаблону.
