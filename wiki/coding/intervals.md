Intervals — класс задач про отрезки $[start, end]$ на прямой: слить пересекающиеся, вставить новый, выбрать максимум непересекающихся, посчитать пиковую нагрузку. Весь раздел стоит на одном факте: интервалы $a$ и $b$ пересекаются тогда и только тогда, когда $a_{\text{start}} \leq b_{\text{end}}$ и $b_{\text{start}} \leq a_{\text{end}}$. Проверять это условие удобнее от противного: не пересекаются — значит, один целиком левее другого.

Почти каждое решение начинается с сортировки: после неё все интервалы, способные пересечься с текущим, стоят рядом, и задача сводится к одному линейному проходу. Единственный содержательный выбор — сортировать по началу (когда сливаем или ищем конфликты) или по концу (когда жадно выбираем непересекающиеся, см. [[greedy]]).

## Сортировка по началу + merge проходом

**Сигнал.** «Слейте пересекающиеся интервалы», «сколько останется после объединения», нужно получить непересекающееся покрытие.

**Идея.** Сортируем по началу — теперь любой интервал может пересекаться только с последним слитым: всё, что левее, уже закрыто. Идём слева направо и держим текущий «растущий» интервал: если новый начинается не позже его конца — расширяем конец через $\max$, иначе пересечений с ним больше не будет, фиксируем и начинаем новый. Один проход, потому что сортировка гарантирует: раз новый интервал не задел текущий, не заденет и никого раньше.

```python
def merge(intervals: list[list[int]]) -> list[list[int]]:
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]
    for start, end in intervals[1:]:
        if start <= merged[-1][1]:      # overlaps the last merged one
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
```

**Типовые задачи:** Merge Intervals, Interval List Intersections (два отсортированных списка — там же [[two-pointers]]).

Сложность: $O(n \log n)$ на сортировку, сам проход $O(n)$.

## Insert Interval — три фазы без пересортировки

**Сигнал.** Список **уже отсортирован** и не пересекается, нужно вставить один новый интервал. Сортировать заново — значит выбросить то, что даёт условие.

**Идея.** Проходим список три фазы: (1) всё, что кончается до начала нового, — копируем как есть; (2) всё, что пересекается с новым, — поглощаем в него, расширяя границы через $\min/\max$; (3) остаток копируем как есть. Новый интервал вставляется ровно один раз — когда пересечения закончились.

```python
def insert(intervals: list[list[int]], new: list[int]) -> list[list[int]]:
    res, i, n = [], 0, len(intervals)
    while i < n and intervals[i][1] < new[0]:   # phase 1: strictly left
        res.append(intervals[i]); i += 1
    while i < n and intervals[i][0] <= new[1]:  # phase 2: overlapping
        new = [min(new[0], intervals[i][0]), max(new[1], intervals[i][1])]
        i += 1
    res.append(new)
    res.extend(intervals[i:])                   # phase 3: strictly right
    return res
```

**Типовые задачи:** Insert Interval.

Сложность: $O(n)$ — сортировка не нужна, порядок уже дан.

## Максимум непересекающихся: сортировка по концу + greedy

**Сигнал.** «Выберите максимум непересекающихся интервалов», «минимум удалений, чтобы не пересекались» — это одна задача: удалить минимум $=$ оставить максимум.

**Идея.** Классический activity selection из [[greedy]]. Сортируем по **концу**: интервал с самым ранним концом освобождает прямую раньше всех, поэтому брать его безопасно — любое другое решение можно обменять на него, не ухудшив. Дальше жадно берём каждый интервал, который начинается не раньше конца последнего взятого. Сортировка по началу здесь ломается: рано начавшийся, но длинный интервал перекрывает кучу коротких.

```python
def erase_overlap_intervals(intervals: list[list[int]]) -> int:
    intervals.sort(key=lambda x: x[1])          # earliest end first
    kept, prev_end = 0, float("-inf")
    for start, end in intervals:
        if start >= prev_end:                   # compatible, keep it
            kept += 1
            prev_end = end
    return len(intervals) - kept                # removals
```

**Типовые задачи:** Non-overlapping Intervals, Maximum Length of Pair Chain.

Сложность: $O(n \log n)$.

## Meeting Rooms I — проверка конфликтов

**Сигнал.** «Может ли один человек посетить все встречи», «есть ли хоть одно пересечение».

**Идея.** После сортировки по началу конфликт возможен только между **соседями**: если $i$-я встреча не задевает $(i{+}1)$-ю, то не задевает и все последующие. Значит, достаточно одного прохода со сравнением $end_i > start_{i+1}$.

```python
def can_attend_meetings(intervals: list[list[int]]) -> bool:
    intervals.sort(key=lambda x: x[0])
    return all(intervals[i][1] <= intervals[i + 1][0] for i in range(len(intervals) - 1))
```

**Типовые задачи:** Meeting Rooms.

Сложность: $O(n \log n)$.

## Meeting Rooms II — минимум ресурсов

**Сигнал.** «Минимум переговорок / платформ / машин», т.е. **максимальное число одновременно активных** интервалов.

**Идея, решение 1 — min-heap концов** (см. [[heap]]). Сортируем по началу, в куче держим времена окончания идущих встреч. Новая встреча: если самая ранняя из идущих уже закончилась ($\text{heap}[0] \leq start$) — переиспользуем её комнату (pop), иначе открываем новую. Размер кучи в конце — ответ. Куча нужна, потому что переиспользовать выгодно именно комнату с минимальным временем освобождения.

**Идея, решение 2 — sweep line.** Каждая встреча — два события: $+1$ в момент начала, $-1$ в момент конца. Отдельно сортируем массивы начал и концов и двигаем два указателя: счётчик активных встреч растёт и падает, его максимум — ответ.

```python
import heapq

def min_meeting_rooms(intervals: list[list[int]]) -> int:
    intervals.sort(key=lambda x: x[0])
    ends: list[int] = []                        # min-heap of end times
    for start, end in intervals:
        if ends and ends[0] <= start:
            heapq.heappop(ends)                 # reuse the freed room
        heapq.heappush(ends, end)
    return len(ends)
```

**Типовые задачи:** Meeting Rooms II, Car Pooling, My Calendar II.

Сложность: $O(n \log n)$ оба решения.

## Sweep line как общий фреймворк

**Сигнал.** Вопрос про **все точки прямой сразу**: максимальная нагрузка, число пересекающихся групп, минимум «выстрелов», покрывающих все интервалы.

**Идея.** Обобщение второго решения Meeting Rooms II: превращаем интервалы в события «начало» / «конец», сортируем и проходим прямую слева направо с префиксным счётчиком активных интервалов. Любой вопрос вида «что происходит в точке $x$» сводится к значению счётчика в момент прохода. Тонкость всегда одна — порядок событий с равной координатой: считаем ли касание пересечением. Для Minimum Number of Arrows достаточно ещё проще: сортируем по концу и жадно стреляем в конец первого непокрытого интервала — одна стрела снимает всю группу, задевающую эту точку.

```python
def max_overlap(intervals: list[list[int]]) -> int:
    events = []
    for start, end in intervals:
        events.append((start, +1))
        events.append((end, -1))                # end before start on ties
    events.sort()
    best = active = 0
    for _, delta in events:
        active += delta
        best = max(best, active)
    return best
```

**Типовые задачи:** Minimum Number of Arrows to Burst Balloons, Points That Intersect With Cars, Number of Flowers in Full Bloom.

Сложность: $O(n \log n)$.

## Интервалы с запросами: offline-сортировка + heap

**Сигнал.** К набору интервалов задано много точечных запросов («самый короткий интервал, содержащий $q$»); онлайн отвечать дорого — сортируем запросы и отвечаем offline.

**Идея.** Сортируем и интервалы, и запросы; идём по запросам слева направо, добавляя в min-heap (по длине) все интервалы, начавшиеся до текущего $q$, и выкидывая из вершины те, что уже закончились ($end < q$) — вершина кучи и есть ответ.

**Типовые задачи:** Minimum Interval to Include Each Query.

Сложность: $O((n + m)\log(n + m))$.

## Карта раздела

| Техника | Сигнал в задаче | Сложность |
|---|---|---|
| Сортировка по началу + merge | «Слейте пересекающиеся» | $O(n \log n)$ |
| Insert Interval, три фазы | Вставка в уже отсортированный список | $O(n)$ |
| Сортировка по концу + greedy | Максимум непересекающихся / минимум удалений | $O(n \log n)$ |
| Соседи после сортировки | «Есть ли хоть один конфликт» | $O(n \log n)$ |
| Heap концов | Минимум одновременных ресурсов | $O(n \log n)$ |
| Sweep line ($\pm 1$-события) | Пиковая нагрузка, покрытие всех интервалов | $O(n \log n)$ |
| Offline-запросы + heap | Много точечных запросов к интервалам | $O((n{+}m)\log(n{+}m))$ |
