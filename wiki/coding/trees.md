Гайд по деревьям для кодинг-интервью. План такой: сначала разберёмся, что такое дерево и какими они бывают, затем — два алгоритма обхода, DFS и BFS, из которых собирается решение почти любой задачи раздела, и BST как особый класс деревьев, где дополнительно работает порядок. Конкретные задачи Neetcode сведены в карту в конце — их два десятка, а идей за ними от силы пять. Деревья для строк живут отдельно в [[tries]].

## Что такое дерево

Дерево — связный граф без циклов. Из определения сразу следует главное структурное свойство: между любыми двумя узлами существует ровно один путь, а в дереве из $n$ узлов ровно $n - 1$ ребро. В задачах дерево почти всегда корневое: один узел объявлен корнем, рёбра направлены от него, у каждого узла один родитель и сколько-то детей. Узел без детей — лист.

Два термина, которые постоянно путают: **глубина** узла — расстояние от корня до него (у корня глубина 0), **высота** дерева — максимальная глубина, то есть длина самого длинного пути от корня до листа.

Для алгоритмов самое важное свойство дерева — его рекурсивное устройство: дерево — это либо пустота, либо корень плюс левое и правое поддеревья, каждое из которых — само по себе дерево. Каждый узел — корень собственного поддерева. Именно поэтому рекурсия на деревьях — не «один из приёмов», а способ мышления, продиктованный самой структурой данных: определение рекурсивно, значит и функции над ним естественно писать рекурсивно, с базой на пустом дереве.

В коде узел — это значение и два указателя; такой класс в задачах обычно дают готовым:

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

Виды деревьев, которые встречаются в условиях как гарантии или требования:

- **Бинарное** — у каждого узла не больше двух детей. Дефолт интервью-задач; n-арное встречается редко и отличается только циклом по `children` вместо пары `left`/`right`.
- **Complete** — все уровни, кроме, возможно, последнего, заполнены целиком, последний заполнен слева направо без дыр. Именно поэтому [[heap]] хранится в массиве без всяких указателей: дети узла $i$ живут в $2i + 1$ и $2i + 2$.
- **Perfect** — заполнены вообще все уровни. Узлов ровно $2^{h+1} - 1$, и примерно половина из них — листья: полезный факт для оценок «сколько работы происходит на нижнем уровне».
- **Balanced** — высота есть $O(\log n)$. В LeetCode-задачах определение обычно жёстче: у каждого узла высоты поддеревьев различаются не больше чем на 1.
- **BST** — бинарное дерево с инвариантом порядка, ему посвящён отдельный раздел ниже.

Почти все сложности на деревьях выражаются через $n$ и высоту $h$. У сбалансированного дерева $h \approx \log_2 n$, у выродившегося в цепочку «бамбука» $h = n - 1$. Поэтому запись $O(h)$ — честнее, чем $O(\log n)$: гарантии баланса обычно нет, и в худшем случае $O(h)$ — это $O(n)$.

## Задача на дерево — это обход

У почти любой задачи раздела один и тот же скелет: систематически обойти все узлы, по дороге что-то вычисляя. Способов обойти дерево два:

- **DFS** (depth-first search) — идём вглубь, пока не упрёмся, потом возвращаемся; реализуется рекурсией или явным стеком.
- **BFS** (breadth-first search) — идём по уровням: сначала корень, потом все узлы глубины 1, потом глубины 2; реализуется очередью.

> [!important]
> DFS и BFS — это весь алгоритмический арсенал раздела. Разнообразие задач — это не разнообразие алгоритмов, а разнообразие того, **какие данные и в какую сторону текут во время обхода**: сверху вниз аргументами рекурсии, снизу вверх возвращаемыми значениями или вбок, в глобальный аккумулятор.

Выбор между ними простой. BFS берём, когда ответ сформулирован в терминах уровней или расстояния от корня — в условии буквально звучит «level», «view», «минимальная глубина». Всё остальное — DFS, и это выбор по умолчанию: рекурсия по структуре дерева естественна. Дерево — частный случай графа, поэтому обе идеи без изменений переносятся в [[graphs]]; там к ним добавится множество visited, которое в дереве не нужно — циклов нет, дважды в один узел не придём.

## DFS: один алгоритм, три порядка, три потока данных

Скелет DFS — прямая калька с рекурсивного определения дерева: база — пустое дерево, шаг — обработать узел и рекурсивно спуститься в детей.

```python
def dfs(node):
    if not node:        # base case: empty tree
        return
    # preorder: process the node BEFORE its subtrees
    dfs(node.left)
    # inorder: BETWEEN the left and right subtree
    dfs(node.right)
    # postorder: AFTER both subtrees
```

Preorder, inorder и postorder — не три разных алгоритма, а три места в одной и той же функции, куда можно вставить обработку узла. Выбор места определяет, что узел «знает» в момент обработки: в preorder узел обрабатывается раньше своих поддеревьев — естественный порядок для передачи информации сверху вниз; в postorder — после, когда оба поддерева уже посчитаны, — порядок для сборки ответа снизу вверх. Inorder специфичен для бинарных деревьев, и его звёздный час — BST, где он выдаёт значения в отсортированном порядке (см. ниже).

Теперь главное обобщение. У рекурсивной функции есть два канала передачи данных: **аргументы** текут вниз, от корня к листьям, а **возвращаемые значения** — вверх, от листьев к корню. Есть и третий канал, внешний по отношению к рекурсии: **аккумулятор**, видимый из всех вызовов (`nonlocal`-переменная или поле класса). Практически любая DFS-задача — это ответ на вопрос «что течёт по каждому из трёх каналов». Разберём все три направления.

### Поток вверх: ответ из поддеревьев

Если свойство дерева выражается через то же свойство его поддеревьев — глубина, равенство двух деревьев, сбалансированность, — ответ собирается снизу вверх: рекурсия возвращает ответ для поддерева, родитель комбинирует ответы детей. По сути это структурная индукция: базу задаёт пустое дерево, шаг — комбинирующая функция

$$
f(\text{node}) = \text{combine}\big(f(\text{node.left}),\ f(\text{node.right}),\ \text{node.val}\big).
$$

Канонический пример — глубина дерева:

```python
def max_depth(root):
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

От задачи к задаче меняется только `combine`: для глубины это $1 + \max$, для инвертирования — поменять детей местами, для равенства двух деревьев — сравнить корни и рекурсивно пары поддеревьев, для сбалансированности — вернуть высоту вместе с флагом. Скелет один, и на интервью полезно так и проговаривать: «это стандартная рекурсия по дереву, мне осталось определить базу и комбинацию».

### Поток вниз: состояние от корня

Обратная ситуация: ответ для узла зависит от пути от корня до него — от максимума на этом пути, от накопленной суммы. Из возвращаемых значений детей эту информацию не достать — она живёт *выше* узла, поэтому несём её вниз аргументом рекурсии. Пример — Count Good Nodes (узел «хороший», если на пути от корня к нему нет значения больше):

```python
def good_nodes(root):
    def dfs(node, path_max):     # path_max: max value on the root-to-node path
        if not node:
            return 0
        good = 1 if node.val >= path_max else 0
        path_max = max(path_max, node.val)
        return good + dfs(node.left, path_max) + dfs(node.right, path_max)
    return dfs(root, float("-inf"))
```

Заметим, что каналы свободно комбинируются: здесь состояние (`path_max`) течёт вниз, а счётчик хороших узлов — вверх. Валидация BST устроена ровно так же — вниз течёт допустимый интервал; мы вернёмся к ней в разделе про BST.

### Оба поддерева сразу: аккумулятор

Задачи про «лучший путь где-то в дереве» — диаметр, максимальная сумма пути — устроены хитрее: искомый путь не обязан проходить через корень, поэтому одного возвращаемого значения не хватает. В каждом узле сосуществуют две разные величины:

- **путь через узел** — проходит через оба поддерева и дальше вверх продолжаться не может; это кандидат в ответ, им обновляем аккумулятор;
- **путь для родителя** — продолжится вверх, поэтому вправе использовать только *одно* поддерево; именно его возвращаем из рекурсии.

```python
def diameter(root):
    best = 0
    def dfs(node):
        nonlocal best
        if not node:
            return 0
        left, right = dfs(node.left), dfs(node.right)
        best = max(best, left + right)   # path through the node -> accumulator
        return 1 + max(left, right)      # path handed to the parent -> upward
    dfs(root)
    return best
```

Перепутать эти две величины — вернуть родителю «путь через узел» — классическая ошибка: родитель получил бы путь, который уже нельзя продолжить. В Maximum Path Sum к шаблону добавляется одна деталь: отрицательный вклад ребёнка заменяем нулём — путь выгоднее оборвать, чем тащить минус.

### Явный стек вместо рекурсии

Рекурсия — это неявный стек вызовов, поэтому любой рекурсивный DFS механически переписывается через явный [[stack]]. Нужно это в двух случаях: когда прямо просят «без рекурсии» и — интереснее — когда нужен *ленивый* обход: итератор по дереву или ранняя остановка (за $k$-м наименьшим элементом незачем обходить всё дерево). Ходовой шаблон — итеративный inorder:

```python
def inorder(root):
    stack, node, res = [], root, []
    while stack or node:
        while node:              # dive left as deep as possible
            stack.append(node)
            node = node.left
        node = stack.pop()
        res.append(node.val)     # next inorder node
        node = node.right
    return res
```

Разрезав внешний `while` на отдельные шаги `next()`, получаем BST Iterator: $O(h)$ памяти и амортизированное $O(1)$ на элемент.

Сложность любого DFS: $O(n)$ по времени — каждый узел посещается один раз; $O(h)$ по памяти — стек, неявный или явный, хранит путь от корня до текущего узла.

## BFS: обход по уровням

Когда ответ сформулирован в терминах уровней — обход по уровням, вид справа, средние по уровням — или расстояния от корня, берём BFS: очередь, из головы достаём узел, в хвост кладём его детей. Единственный трюк, отличающий деревянный BFS от графового: в начале итерации фиксируем `len(queue)` — в этот момент очередь содержит ровно один уровень, и мы вычерпываем ровно столько узлов, докидывая детей в хвост. Без фиксации размера уровни в очереди смешиваются, и границу между ними уже не восстановить — а, скажем, «последний узел уровня» для Right Side View требует именно границы.

```python
from collections import deque

def level_order(root):
    if not root:
        return []
    res, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):   # freeze current level size
            node = queue.popleft()
            level.append(node.val)
            if node.left:  queue.append(node.left)
            if node.right: queue.append(node.right)
        res.append(level)
    return res
```

Отдельного упоминания стоит минимальная глубина: BFS остановится на первом же встреченном листе, тогда как DFS вынужден обойти всё дерево. Это частный случай общего правила из [[graphs]]: всё «кратчайшее от старта» ищется BFS-ом, потому что он посещает узлы в порядке возрастания расстояния.

Сложность: $O(n)$ по времени, $O(w)$ по памяти, где $w$ — максимальная ширина уровня. Здесь любопытный контраст с DFS: у сбалансированного дерева нижний уровень содержит около $n/2$ узлов, так что BFS платит $O(n)$ памяти там, где DFS обходится $O(\log n)$; у «бамбука» всё ровно наоборот. Выбор обхода — это ещё и выбор, чем платить: глубиной или шириной.

## BST: дерево, в котором работает порядок

BST (binary search tree) — бинарное дерево с инвариантом: для каждого узла **всё** его левое поддерево строго меньше него, а **всё** правое — строго больше. Ключевое слово — «всё»: инвариант глобальный, и сравнивать узел только с непосредственными детьми недостаточно. Дерево «5, слева 3, у тройки справа 7» локально выглядит прилично (каждый ребёнок на своём месте относительно родителя), но 7 сидит в левом поддереве пятёрки — инвариант нарушен на расстоянии двух уровней.

Из одного инварианта вытекают три рабочих следствия.

**Спуск за $O(h)$.** Поиск, вставка и LCA не требуют обхода всего дерева: одно сравнение с узлом говорит, в какое поддерево идти, и второе поддерево отбрасывается целиком. Это прямой родственник [[binary-search]] — только «середина» задана не индексом, а структурой дерева. LCA двух узлов ищется тем же спуском: пока $p$ и $q$ оба меньше текущего узла, идём влево; оба больше — вправо; первый узел, разделяющий их (или совпавший с одним из них), и есть ответ.

```python
def lca_bst(root, p, q):
    while root:
        if p.val < root.val and q.val < root.val:   root = root.left
        elif p.val > root.val and q.val > root.val: root = root.right
        else:                                       return root
```

**Inorder выдаёт отсортированный порядок.** Сначала обходится левое поддерево (всё меньшее), потом узел, потом правое (всё большее) — по индукции значения выходят строго по возрастанию. Отсюда kth smallest без всякой сортировки и без [[heap]]: итеративный inorder с остановкой после $k$-го узла.

**Валидация — это DFS сверху вниз.** Раз инвариант глобальный, узел должен удовлетворять ограничениям *всех* своих предков — спускаем их вниз одним допустимым интервалом $(lo, hi)$: уходя влево, опускаем потолок до значения узла, уходя вправо — поднимаем пол. Тот же поток данных вниз, что в good nodes, — BST не потребовал нового алгоритма.

```python
def is_valid_bst(root):
    def dfs(node, lo, hi):
        if not node:
            return True
        if not (lo < node.val < hi):
            return False
        return dfs(node.left, lo, node.val) and dfs(node.right, node.val, hi)
    return dfs(root, float("-inf"), float("inf"))
```

Все $O(h)$-гарантии упираются в высоту: если вставлять в BST отсортированные ключи, он выродится в бамбук, и $O(h)$ превратится в $O(n)$. Лекарство — **самобалансирующиеся деревья** (AVL, red-black): при каждой вставке и удалении они локальными поворотами восстанавливают баланс и тем гарантируют $h = O(\log n)$. Реализовывать их на интервью не просят, но знать нужно вот что: когда требуется «отсортированное множество с $O(\log n)$ вставкой, удалением и поиском соседей», ответ — именно они: `std::map` в C++, `TreeMap` в Java; в стандартной библиотеке Python аналога нет, на практике берут `sortedcontainers`.

## Обход как представление дерева

До сих пор обход был способом что-то по дереву посчитать. Есть и второй взгляд: последовательность посещённых узлов — это *код* дерева, по которому его можно построить обратно. Правда, один список значений сам по себе дерево не задаёт: preorder $[1, 2]$ — это «2 слева» или «2 справа»? Однозначность восстанавливают двумя способами, и оба — популярные интервью-задачи.

**Два обхода: preorder + inorder.** Первый элемент preorder — корень всего дерева. Находим его в inorder: всё, что левее, — левое поддерево, всё, что правее, — правое. Рекурсия повторяет то же самое на половинках, а preorder удобно вычерпывать общим итератором: порядок корней в нём в точности совпадает с порядком рекурсивных вызовов. Два ускорения, ожидаемые на интервью: hashmap значение $\to$ индекс в inorder вместо линейного поиска и границы окна $[lo, hi)$ вместо срезов списков — вместе они опускают наивные $O(n^2)$ до $O(n)$.

```python
def build_tree(preorder, inorder):
    idx = {v: i for i, v in enumerate(inorder)}
    pre = iter(preorder)
    def build(lo, hi):                  # inorder window [lo, hi)
        if lo >= hi:
            return None
        root = TreeNode(next(pre))
        mid = idx[root.val]
        root.left = build(lo, mid)      # call order == preorder order
        root.right = build(mid + 1, hi)
        return root
    return build(0, len(inorder))
```

**Один обход с null-маркерами: сериализация.** Если писать в preorder не только значения, но и пустые поддеревья (маркер `#`), неоднозначность исчезает: вместо $[1, 2]$ получится либо $[1, 2, \#, \#, \#]$ (двойка слева), либо $[1, \#, 2, \#, \#]$ (двойка справа). Кодер — обычный preorder DFS; декодер — зеркальная рекурсия по общему итератору токенов: каждый вызов съедает ровно свои токены, никаких индексов руками.

```python
def serialize(root):
    out = []
    def dfs(node):
        if not node:
            out.append("#")
            return
        out.append(str(node.val))
        dfs(node.left)
        dfs(node.right)
    dfs(root)
    return ",".join(out)

def deserialize(data):
    it = iter(data.split(","))
    def dfs():
        val = next(it)
        if val == "#":
            return None
        node = TreeNode(int(val))
        node.left, node.right = dfs(), dfs()
        return node
    return dfs()
```

Оба представления — $O(n)$ по времени и памяти в обе стороны. Приятное побочное следствие сериализации: поддеревья можно сравнивать как строки — например, складывать их коды в hashmap и так находить дубликаты (Find Duplicate Subtrees).

Задачи раздела Trees, разложенные по идеям выше. Колонка «деталь» — то единственное, чем задача отличается от голого шаблона; всё остальное в ней — шаблон как есть.

| Задача | Идея | Деталь |
| --- | --- | --- |
| Maximum Depth of Binary Tree | DFS вверх | combine = $1 + \max$ |
| Invert Binary Tree | DFS вверх | combine = поменять детей местами |
| Same Tree | DFS вверх | рекурсия по паре узлов |
| Subtree of Another Tree | DFS вверх | same tree, запущенный в каждом узле |
| Balanced Binary Tree | DFS вверх | возвращаем высоту вместе с флагом |
| Diameter of Binary Tree | DFS вверх + аккумулятор | путь через узел vs путь для родителя |
| Binary Tree Maximum Path Sum | DFS вверх + аккумулятор | отрицательный вклад ребёнка $\to 0$ |
| Count Good Nodes in Binary Tree | DFS вниз | несём максимум на пути |
| Path Sum I/II | DFS вниз | несём остаток целевой суммы |
| Validate Binary Search Tree | DFS вниз | несём интервал $(lo, hi)$ |
| Binary Tree Level Order Traversal | BFS | шаблон как есть |
| Binary Tree Right Side View | BFS | берём последний узел уровня |
| Minimum Depth of Binary Tree | BFS | стоп на первом листе |
| Zigzag Level Order Traversal | BFS | разворачиваем нечётные уровни |
| Kth Smallest Element in a BST | BST: sorted inorder | итеративно, ранний выход после $k$ узлов |
| Binary Search Tree Iterator | BST: sorted inorder | итеративный inorder, разрезанный на `next()` |
| Lowest Common Ancestor of a BST | BST: спуск за $O(h)$ | точка развилки между $p$ и $q$ |
| Insert / Delete in a BST | BST: спуск за $O(h)$ | delete: замена на inorder-соседа |
| Construct from Preorder and Inorder | обход как код | hashmap индексов + окна |
| Serialize and Deserialize Binary Tree | обход как код | preorder с null-маркерами |
| Find Duplicate Subtrees | обход как код | код поддерева $\to$ hashmap |

Двадцать одна задача — и пять строчек в колонке «идея»: DFS с потоком вверх, вниз или с аккумулятором, BFS по уровням, следствия BST-инварианта и обход как код дерева. Ровно это и стоит уносить с собой: распознать, какие данные куда текут, — и задача сводится к шаблону.
