Greedy — стратегия «на каждом шаге делаем локально оптимальный выбор и никогда не откатываемся». Ни рекурсии, ни таблицы состояний: один проход, одно текущее решение. Корректность держится на **greedy-choice property**: существует оптимальное решение, которое начинается с жадного выбора. Стандартный способ это доказать — **exchange argument**: берём любое оптимальное решение, находим первое место, где оно расходится с жадным, и меняем его выбор на жадный. Если после обмена решение не стало хуже — значит, жадный выбор ничего не портит, и по индукции весь жадный ответ оптимален.

Как отличить greedy-задачу от DP-задачи: пробуем exchange argument на пальцах. Если чужой выбор всегда можно «обменять» на жадный без потерь — это greedy. Если же лучший ход зависит от того, что будет дальше, и приходится тащить несколько состояний-кандидатов — это перебор состояний, то есть [[dp-1d]] или [[dp-2d]]. Greedy — вырожденный DP с одним состоянием; поэтому многие задачи ниже имеют и DP-формулировку, просто жадная короче.

## Kadane: сброс отрицательного префикса

**Сигнал.** «Maximum sum subarray» — contiguous, без ограничения на длину.

**Идея.** Идём слева направо и держим лучшую сумму отрезка, заканчивающегося здесь. Ключевое наблюдение: отрицательный префикс никогда не помогает — если сумма накопленного куска ушла в минус, любое продолжение только выиграет от его отбрасывания, поэтому начинаем отрезок заново. Это exchange argument в чистом виде: заменяем «тащить минусовый хвост» на «начать с текущего элемента» и не проигрываем. Формально это [[dp-1d]] с одним состоянием: $\text{cur}_i = \max(x_i,\ \text{cur}_{i-1} + x_i)$ — вся таблица схлопнулась в одну переменную.

```python
def max_subarray(nums: list[int]) -> int:
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)   # negative prefix never helps -> drop it
        best = max(best, cur)
    return best
```

**Типовые задачи:** Maximum Subarray, Maximum Product Subarray (уже [[dp-1d]]: нужны два состояния, max и min).

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Расширение достижимой границы

**Сигнал.** Прыжки по массиву: «can you reach the last index», «minimum number of jumps».

**Идея.** Держим `reach` — самый дальний индекс, достижимый из уже просмотренных. Если текущий индекс вылез за `reach`, дальше пути нет. Неважно, *как именно* мы сюда добрались — важна только граница: любые два пути с одинаковым `reach` взаимозаменяемы, это и есть обмен. Для минимума прыжков добавляем «уровни»: все индексы, достижимые за $j$ прыжков, образуют отрезок — по сути это BFS по слоям (интуиция из [[graphs]]), где слой хранится двумя числами вместо очереди.

```python
def can_jump(nums: list[int]) -> bool:
    reach = 0
    for i, x in enumerate(nums):
        if i > reach:
            return False        # gap: index i is unreachable
        reach = max(reach, i + x)
    return True

def jump(nums: list[int]) -> int:
    jumps = cur_end = far = 0
    for i in range(len(nums) - 1):
        far = max(far, i + nums[i])
        if i == cur_end:        # finished current BFS level
            jumps += 1
            cur_end = far
    return jumps
```

**Типовые задачи:** Jump Game, Jump Game II, Video Stitching.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Глобальный инвариант вместо локальной проверки

**Сигнал.** Круговой маршрут / ресурс с пополнением и тратами: «найти стартовую точку, с которой получится обойти круг».

**Идея.** Два уровня рассуждения. Глобальный: если $\sum \text{gas} \geq \sum \text{cost}$, решение существует — суммарного топлива хватает, вопрос только где стартовать. Локальный: если, стартовав из $s$, мы заглохли на станции $i$, то и любой старт между $s$ и $i$ заглохнет там же — он приезжает в каждую точку с не большим баком (стартует с нуля, а не с накопленным плюсом). Значит, следующего кандидата можно смело брать за точкой провала — перебор из $O(n^2)$ схлопывается в один проход.

```python
def can_complete_circuit(gas: list[int], cost: list[int]) -> int:
    if sum(gas) < sum(cost):
        return -1               # global invariant: total fuel must suffice
    tank = start = 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:            # no start in [start..i] can pass i
            start, tank = i + 1, 0
    return start
```

**Типовые задачи:** Gas Station, Maximum Score of a Good Subarray (родственная логика границ).

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Сортировка + жадный проход

**Сигнал.** Порядок обработки не задан условием, но у элементов есть естественный «самый ограниченный» — самый ранний конец, самое маленькое значение. Сортируем, чтобы жадный выбор стал очевидным.

**Идея.** После сортировки exchange argument почти всегда звучит одинаково: «самый ограниченный элемент всё равно придётся обслужить — обслужим его первым, это блокирует меньше всего вариантов». Классика из [[intervals]] — Non-overlapping Intervals: сортируем по правому концу и оставляем интервал с самым ранним концом, он оставляет максимум места остальным. Здесь покажем Hand of Straights: минимальная оставшаяся карта обязана начинать свою группу — больше ей быть некем, — поэтому берём её и жадно добираем $k$ подряд идущих через `Counter` (hash map из [[arrays-hashing]]).

```python
from collections import Counter

def is_n_straight_hand(hand: list[int], k: int) -> bool:
    if len(hand) % k:
        return False
    count = Counter(hand)
    for x in sorted(count):
        while count[x]:         # smallest card must start its group
            for y in range(x, x + k):
                if not count[y]:
                    return False
                count[y] -= 1
    return True
```

**Типовые задачи:** Hand of Straights, Non-overlapping Intervals (см. [[intervals]]), Least Number of Unique Integers after K Removals, Two City Scheduling. Когда минимум нужен динамически, вместо сортировки берём [[heap]].

Сложность: $O(n \log n)$ на сортировку плюс линейный проход.

## Границы диапазона вместо перебора

**Сигнал.** Wildcard-символы с несколькими интерпретациями — наивно это ветвление в [[backtracking]] с экспонентой, но от состояния нужен только счётчик.

**Идея.** Вместо перебора всех интерпретаций храним **диапазон** возможных значений счётчика. В Valid Parenthesis String это число незакрытых скобок: `lo` — если каждая `*` работает на уменьшение, `hi` — если на увеличение. Диапазон целых значений сплошной, поэтому пара границ описывает все ветки сразу. Если $hi < 0$ — перебор `)` даже в лучшем случае, отказ; `lo` подрезаем нулём — счётчик открытых скобок не бывает отрицательным. Строка валидна, если в конце $lo = 0$: ноль лежит в диапазоне достижимого.

```python
def check_valid_string(s: str) -> bool:
    lo = hi = 0                 # range of possible open counts
    for ch in s:
        lo += 1 if ch == "(" else -1
        hi += 1 if ch != ")" else -1
        if hi < 0:
            return False        # too many ')' whatever '*' means
        lo = max(lo, 0)         # open count can't go negative
    return lo == 0
```

**Типовые задачи:** Valid Parenthesis String, Minimum Add to Make Parentheses Valid.

Сложность: $O(n)$ по времени, $O(1)$ по памяти — против $O(2^n)$ у наивного перебора.

## Partition Labels: расширение куска до последнего вхождения

**Сигнал.** Разрезать последовательность на максимум кусков так, чтобы каждый элемент целиком жил в одном куске.

**Идея.** Предподсчитываем последнее вхождение каждого символа (hash map, [[arrays-hashing]]). Идём по строке и держим `end` — правую границу, до которой текущий кусок *обязан* дотянуться: каждый встреченный символ отодвигает её до своего последнего вхождения. Как только дошли до `end`, кусок закрывать безопасно — ни один его символ дальше не встречается, — и жадно закрываем: резать раньше нельзя, а резать позже значит склеить два допустимых куска, что только уменьшит их число.

```python
def partition_labels(s: str) -> list[int]:
    last = {ch: i for i, ch in enumerate(s)}
    res, start, end = [], 0, 0
    for i, ch in enumerate(s):
        end = max(end, last[ch])   # chunk must cover every seen char
        if i == end:               # safe to cut: nothing leaks right
            res.append(i - start + 1)
            start = i + 1
    return res
```

**Типовые задачи:** Partition Labels, Merge Intervals (та же логика растущей правой границы, см. [[intervals]]).

Сложность: $O(n)$ по времени, $O(|\Sigma|)$ по памяти.

## Покомпонентные ограничения: фильтрация кандидатов

**Сигнал.** Собрать цель из элементов операцией вроде покомпонентного $\max$/$\min$/OR — монотонной: добавление элемента никогда не уменьшает уже достигнутое.

**Идея.** Раз операция монотонна, единственный способ всё испортить — взять элемент, который где-то *превышает* цель: этого уже не откатить. Поэтому жадное правило — выкинуть всех недопустимых кандидатов, а всех допустимых можно смело брать разом: хуже они не сделают. Остаётся проверить, покрывают ли выжившие каждую компоненту цели. Никакого подбора комбинаций — фильтр плюс проверка покрытия.

```python
def merge_triplets(triplets: list[list[int]], target: list[int]) -> bool:
    good = [False] * 3
    for t in triplets:
        if all(t[i] <= target[i] for i in range(3)):  # never overshoots
            for i in range(3):
                good[i] |= t[i] == target[i]
    return all(good)
```

**Типовые задачи:** Merge Triplets to Form Target Triplet, Maximum Bags With Full Capacity of Rocks. Побитовая версия того же рассуждения встречается в [[bit-manipulation]] (OR как монотонная операция).

Сложность: $O(n)$ по времени, $O(1)$ по памяти.
