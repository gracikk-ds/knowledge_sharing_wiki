Stack — раздел про задачи, где порядок обработки LIFO: последний добавленный элемент нужен первым. Классические сигналы: вложенные структуры (скобки, теги, вложенные строки), правило «последний открытый — первый закрытый», вопрос «ближайший следующий/предыдущий больший или меньший элемент», а также любая ситуация, где новый элемент может «отменить» или «поглотить» несколько предыдущих.

Стек здесь — не столько структура данных, сколько способ хранить *незакрытые обязательства*: всё, что уже встретили, но ещё не смогли обработать до конца. Как только приходит элемент, который закрывает обязательство, мы снимаем его с вершины. Главный фреймворк раздела — monotonic stack: на нём держится добрая половина задач.

## Стек для парных структур

**Сигнал.** Скобки, теги, пары «открыл — закрыл», проверка корректности вложенности. Любая грамматика вида «закрывающий элемент должен соответствовать последнему открытому».

**Идея.** Открывающие элементы кладём в стек, закрывающий обязан совпасть с вершиной — иначе структура сломана. Вложенность и LIFO — одно и то же: внутренняя скобка открыта последней и закрыта первой. В конце стек должен быть пуст, иначе остались незакрытые обязательства.

```python
def is_valid(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return not stack
```

**Типовые задачи:** Valid Parentheses, Minimum Remove to Make Valid Parentheses, Decode String, Simplify Path.

Сложность: $O(n)$ по времени, $O(n)$ по памяти.

## Стек с дополнительным состоянием

**Сигнал.** Обычные операции стека плюс запрос агрегата по текущему содержимому за $O(1)$: минимум, максимум.

**Идея.** Пересчитывать минимум при `pop` нельзя — информация потеряна. Вместо этого храним в каждом элементе снапшот «минимум на момент моего добавления»: пара `(value, min_so_far)` или параллельный стек минимумов. При `pop` снапшот уходит вместе с элементом, и вершина снова хранит актуальный минимум.

```python
class MinStack:
    def __init__(self):
        self.stack = []  # (value, min of stack up to here)

    def push(self, val: int) -> None:
        cur_min = min(val, self.stack[-1][1]) if self.stack else val
        self.stack.append((val, cur_min))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def get_min(self) -> int:
        return self.stack[-1][1]
```

**Типовые задачи:** Min Stack, Max Stack.

Сложность: $O(1)$ на операцию, $O(n)$ по памяти.

## Стек для вычисления выражений

**Сигнал.** Вычислить выражение: postfix-нотация (RPN), инфиксная строка со скобками, вложенные конструкции, которые нужно «схлопывать» изнутри наружу.

**Идея.** В RPN операнды кладём в стек, оператор снимает два верхних, применяется и кладёт результат обратно — стек хранит ещё не использованные промежуточные значения. Для инфиксных выражений со скобками тот же приём: при `(` сохраняем текущий контекст в стек, при `)` восстанавливаем и комбинируем. Важная мелочь: порядок операндов — первым с вершины снимается *правый*.

```python
def eval_rpn(tokens: list[str]) -> int:
    ops = {"+": lambda a, b: a + b, "-": lambda a, b: a - b,
           "*": lambda a, b: a * b, "/": lambda a, b: int(a / b)}
    stack = []
    for tok in tokens:
        if tok in ops:
            b, a = stack.pop(), stack.pop()  # b is the right operand
            stack.append(ops[tok](a, b))
        else:
            stack.append(int(tok))
    return stack[0]
```

**Типовые задачи:** Evaluate Reverse Polish Notation, Basic Calculator I/II, Decode String.

Сложность: $O(n)$ по времени и памяти.

## Monotonic stack: next greater / smaller

**Сигнал.** «Для каждого элемента найти ближайший следующий/предыдущий больший/меньший», «сколько дней ждать более тёплого дня», span-задачи. Наивно это $O(n^2)$ — верный знак, что нужен monotonic stack.

**Идея.** Держим в стеке индексы элементов, значения которых монотонны (для next greater — убывают): это элементы, которые всё ещё *ждут* своего ответа. Новый элемент выталкивает с вершины всех, кто меньше него, — для каждого вытолкнутого он и есть ближайший больший справа. Кто остался в стеке — продолжает ждать. Каждый элемент входит в стек один раз и выходит один раз, поэтому суммарно все `while`-выталкивания стоят $O(n)$ — амортизация.

> [!important]
> Четыре варианта задачи задаются двумя переключателями: направление прохода (слева направо — ответ «следующий», справа налево — «предыдущий»; либо всегда слева направо, и тогда ответ вытолкнутым — «следующий», а новый top после выталкивания — «предыдущий») и знак сравнения при выталкивании (`<` — next greater, `>` — next smaller; строгость знака решает, как обрабатывать равные элементы).

```python
def daily_temperatures(temps: list[int]) -> list[int]:
    res = [0] * len(temps)
    stack = []  # indices; temps[stack] is decreasing
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            res[j] = i - j  # t is the next greater for temps[j]
        stack.append(i)
    return res
```

**Типовые задачи:** Daily Temperatures, Next Greater Element I/II (II — циклический массив, проходим дважды), Online Stock Span, Sum of Subarray Minimums.

Сложность: $O(n)$ по времени (амортизированно), $O(n)$ по памяти.

## Monotonic stack для площадей

**Сигнал.** Максимальная площадь/объём в гистограмме или матрице; для каждого элемента нужны *обе* границы — ближайший меньший слева и справа.

**Идея.** Максимальный прямоугольник с высотой бара $h_j$ тянется влево и вправо до ближайших баров ниже $h_j$ — они и есть границы. Возрастающий monotonic stack даёт обе границы в момент выталкивания: текущий индекс $i$ — правая граница (первый бар ниже справа), новая вершина стека после `pop` — левая. Ширина прямоугольника получается $i - \text{left} - 1$. Sentinel-ноль в конце вытаскивает из стека всех оставшихся.

```python
def largest_rectangle_area(heights: list[int]) -> int:
    stack = []  # indices; heights increasing
    best = 0
    for i, h in enumerate(heights + [0]):  # sentinel flushes the stack
        while stack and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            left = stack[-1] if stack else -1  # nearest smaller to the left
            best = max(best, height * (i - left - 1))
        stack.append(i)
    return best
```

**Типовые задачи:** Largest Rectangle in Histogram, Maximal Rectangle (гистограмма по каждой строке матрицы, пересекается с [[dp-2d]]), Trapping Rain Water (есть и стековое решение, и решение через [[two-pointers]]).

Сложность: $O(n)$ по времени, $O(n)$ по памяти.

## Сортировка + стек «флотов»

**Сигнал.** Объекты движутся к общей цели и при догоне сливаются в группу (fleet), обгон невозможен. Вопрос — сколько групп доедет.

**Идея.** Сортируем по позиции от ближайшей к цели и считаем время прибытия каждой машины, как если бы она ехала одна. Машина сзади догоняет флот впереди тогда и только тогда, когда её время прибытия не больше — тогда она вливается в него и наследует его время. Стек хранит времена лидеров флотов; ответ — размер стека. По сути это [[greedy]] поверх сортировки, стек здесь монотонно возрастающий по времени.

```python
def car_fleet(target: int, position: list[int], speed: list[int]) -> int:
    cars = sorted(zip(position, speed), reverse=True)  # closest to target first
    stack = []  # arrival times of fleet leaders
    for pos, spd in cars:
        time = (target - pos) / spd
        if not stack or time > stack[-1]:  # cannot catch the fleet ahead
            stack.append(time)
    return len(stack)
```

**Типовые задачи:** Car Fleet.

Сложность: $O(n \log n)$ по времени (сортировка), $O(n)$ по памяти.

## Стек vs рекурсия

**Сигнал.** Любую рекурсию можно развернуть в цикл с явным стеком — сам call stack и есть стек. Нужно, когда глубина рекурсии опасна (вырожденное дерево, лимит Python в ~1000 кадров) или когда обход хочется останавливать и возобновлять (итераторы, BST iterator).

**Идея.** Кладём в стек то, что рекурсия держала бы в кадрах вызова: узлы, которые предстоит посетить. Порядок укладки обратен порядку обработки — LIFO. Итеративные DFS и обходы дерева разобраны в [[trees]] и [[graphs]]; Generate Parentheses, которую Neetcode кладёт в раздел Stack, по сути перебор с откатом — см. [[backtracking]].

```python
def dfs_iterative(root: Node | None) -> None:
    stack = [root]
    while stack:
        node = stack.pop()
        if node is None:
            continue
        visit(node)  # preorder position
        stack.append(node.right)  # right first, so left is processed first
        stack.append(node.left)
```

**Типовые задачи:** Binary Tree Inorder Traversal (iterative), Binary Search Tree Iterator, Generate Parentheses (как [[backtracking]]), итеративный DFS в [[graphs]].

Сложность: $O(n)$ по времени для дерева, $O(V + E)$ для графа; память $O(h)$ — глубина стека.

## Карта раздела

| Техника | Сигнал в задаче | Сложность |
| --- | --- | --- |
| Парные структуры | скобки, вложенность, «последний открытый — первый закрытый» | $O(n)$ |
| Стек с состоянием | min/max текущего содержимого за $O(1)$ | $O(1)$ на операцию |
| Вычисление выражений | RPN, выражения со скобками, вложенные строки | $O(n)$ |
| Monotonic stack | ближайший следующий/предыдущий больший/меньший, span | $O(n)$ амортизированно |
| Monotonic stack для площадей | max площадь, границы по ближайшим меньшим с двух сторон | $O(n)$ |
| Сортировка + флоты | объекты движутся к цели и сливаются при догоне | $O(n \log n)$ |
| Явный стек vs рекурсия | итеративный DFS, опасная глубина рекурсии, паузы обхода | $O(V + E)$ |
