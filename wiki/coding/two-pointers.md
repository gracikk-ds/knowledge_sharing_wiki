Two pointers — класс задач, где вместо перебора всех пар за $O(n^2)$ мы двигаем по последовательности два индекса, и каждый шаг **безопасно отбрасывает** целый пласт кандидатов. Вся техника держится на одном вопросе: «почему, сдвинув указатель, мы гарантированно не потеряли ответ?». Если на него есть ответ через инвариант — задача решается за $O(n)$.

Сигналы, что мы в этом разделе: массив **отсортирован** (или его можно отсортировать), ищется **пара/тройка** с условием на сумму, требуется **in-place** модификация без лишней памяти, проверяется **палиндром** или симметрия. Близкие соседи: [[sliding-window]] (два указателя, движущиеся в одну сторону и держащие «окно»), [[binary-search]] (тоже отбрасывание половины кандидатов, но делением), [[arrays-hashing]] (когда массив не отсортирован и сортировать нельзя — пары ищем через hash map).

## Указатели с противоположных концов

**Сигнал.** Отсортированный массив + поиск пары с условием на сумму; или проверка симметрии строки (палиндром).

**Идея.** Ставим $l = 0$, $r = n-1$. Если $a_l + a_r < \text{target}$, то $a_l$ в паре с **любым** $r' < r$ даёт сумму ещё меньше — значит, $a_l$ бесполезен целиком, двигаем $l$. Симметрично при переборе: двигаем $r$. Каждый шаг честно исключает одного кандидата со всеми его парами, поэтому за $n$ шагов мы перебрали все «перспективные» пары, ничего не потеряв. Для палиндрома логика проще: сравниваем зеркальные позиции и сходимся к центру.

```python
def two_sum_sorted(nums: list[int], target: int) -> tuple[int, int]:
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:
            return l, r
        if s < target:
            l += 1  # nums[l] is too small for any partner
        else:
            r -= 1  # nums[r] is too large for any partner
```

**Типовые задачи:** Valid Palindrome, Two Sum II — Input Array Is Sorted, Valid Palindrome II.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Сортировка + два указателя с пропуском дубликатов

**Сигнал.** Найти **все** пары/тройки с заданной суммой, ответ без дубликатов, порядок элементов не важен.

**Идея.** Сортируем ($O(n \log n)$ — дешевле, чем перебор), фиксируем первый элемент и ищем остальные два предыдущей техникой. Дубликаты в ответе убиваются на входе: если текущий элемент равен предыдущему, вся его комбинаторика уже перебрана — пропускаем. Это дешевле, чем складывать тройки в set.

```python
def three_sum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue  # skip duplicate anchors
        l, r = i + 1, len(nums) - 1
        while l < r:
            s = nums[i] + nums[l] + nums[r]
            if s < 0:
                l += 1
            elif s > 0:
                r -= 1
            else:
                res.append([nums[i], nums[l], nums[r]])
                l += 1
                while l < r and nums[l] == nums[l - 1]:
                    l += 1  # skip duplicate seconds
    return res
```

**Типовые задачи:** 3Sum, 3Sum Closest, 4Sum (ещё один внешний цикл).

Сложность: $O(n^2)$ по времени для 3Sum, $O(1)$ дополнительной памяти (не считая сортировки).

## Container With Most Water — жадное движение меньшей стороны

**Сигнал.** Два конца «держат» значение, которое ограничено **минимумом** из них (площадь, объём).

**Идея.** Площадь $(r - l) \cdot \min(h_l, h_r)$. Двигаем указатель с **меньшей** высотой. Почему не теряем оптимум: пока меньшая сторона стоит на месте, любая пара с ней и более узкой шириной имеет высоту не больше (она всё ещё capped меньшей стороной) и ширину строго меньше — все такие пары доминированы текущей, их можно не смотреть. Значит, меньшую сторону можно отбросить целиком.

```python
def max_area(height: list[int]) -> int:
    l, r, best = 0, len(height) - 1, 0
    while l < r:
        best = max(best, (r - l) * min(height[l], height[r]))
        if height[l] < height[r]:
            l += 1  # smaller side caps the area, discard it
        else:
            r -= 1
    return best
```

**Типовые задачи:** Container With Most Water.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Trapping Rain Water двумя указателями

**Сигнал.** Вода/уровень над каждой позицией определяется как $\min(\text{max слева}, \text{max справа}) - h_i$.

**Идея.** Держим `left_max` и `right_max` — максимумы на уже пройденных префиксе и суффиксе. Инвариант: **двигаем сторону с меньшим max**. Если $\text{left\_max} < \text{right\_max}$, то вода над позицией $l$ равна ровно $\text{left\_max} - h_l$: справа гарантированно есть стена не ниже right_max, значит лимитирует левая сторона, и ответ для $l$ уже известен — фиксируем и двигаем. Альтернативы: два прохода с prefix/suffix max-массивами ($O(n)$ памяти, зато прозрачнее) и monotonic stack — разбор в [[stack]].

```python
def trap(height: list[int]) -> int:
    l, r = 0, len(height) - 1
    left_max = right_max = water = 0
    while l < r:
        if height[l] < height[r]:
            left_max = max(left_max, height[l])
            water += left_max - height[l]
            l += 1
        else:
            right_max = max(right_max, height[r])
            water += right_max - height[r]
            r -= 1
    return water
```

**Типовые задачи:** Trapping Rain Water.

Сложность: $O(n)$ по времени, $O(1)$ по памяти (против $O(n)$ у варианта с prefix-массивами).

## Писатель и читатель: in-place удаление и сжатие

**Сигнал.** «Удалите/переместите элементы in-place», «верните новую длину», $O(1)$ extra memory.

**Идея.** Оба указателя идут в одну сторону: `read` честно сканирует всё, `write` отмечает границу уже построенного результата. Инвариант: префикс $[0, \text{write})$ — это готовый ответ на уже прочитанной части. Элементы за `write` нам не нужны — их можно затирать, потому что `read` всегда впереди и уже их видел.

```python
def remove_duplicates(nums: list[int]) -> int:
    write = 1
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return write  # prefix [0, write) is the answer
```

**Типовые задачи:** Remove Duplicates from Sorted Array (I/II), Move Zeroes, Remove Element, String Compression.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Fast & slow pointers (алгоритм Флойда)

**Сигнал.** Поиск цикла или середины в структуре, где можно только идти вперёд (linked list, функциональный граф $i \to \text{nums}[i]$), память $O(1)$.

**Идея.** Быстрый указатель шагает по 2, медленный по 1. Если цикл есть — быстрый «догонит» медленного внутри цикла, потому что расстояние между ними сокращается на 1 за шаг. Вторая фаза Флойда находит начало цикла. Тот же приём даёт середину списка (fast дошёл до конца — slow на середине). Подробный разбор с доказательством — в [[linked-list]]; там же Linked List Cycle и Find the Duplicate Number как цикл в функциональном графе.

**Типовые задачи:** Linked List Cycle I/II, Middle of the Linked List, Find the Duplicate Number, Happy Number.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Партиционирование: Dutch national flag

**Сигнал.** Разложить массив на 2–3 группы по значению in-place за один проход (нули/единицы/двойки, чёт/нечет, меньше/больше pivot).

**Идея.** Три указателя режут массив на зоны: $[0, \text{low})$ — нули, $[\text{low}, \text{mid})$ — единицы, $(\text{high}, n)$ — двойки, а $[\text{mid}, \text{high}]$ — ещё не разобранное. Каждый шаг либо сужает неразобранную зону, либо расширяет одну из готовых — инвариант зон сохраняется, поэтому по окончании массив отсортирован. Это же партиционирование — сердце quickselect и quicksort.

```python
def sort_colors(nums: list[int]) -> None:
    low, mid, high = 0, 0, len(nums) - 1
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = nums[mid], nums[low]
            low += 1
            mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = nums[high], nums[mid]
            high -= 1  # swapped-in value is unseen, don't move mid
    # zones: [0,low) zeros | [low,mid) ones | (high,n) twos
```

**Типовые задачи:** Sort Colors, Partition Array According to Given Pivot, Sort Array By Parity.

Сложность: $O(n)$ по времени, $O(1)$ по памяти.

## Два указателя по двум последовательностям

**Сигнал.** Две отсортированные последовательности, нужно их слить/пересечь; или проверка «является ли $s$ подпоследовательностью $t$».

**Идея.** По указателю на каждую последовательность, на каждом шаге двигается тот, чей элемент «меньше» (merge) или «совпал» (subsequence). Работает по той же причине, что и merge step в merge sort: меньший из двух текущих элементов уже не может встретиться дальше, его судьба решена. Для merge в конец массива (Merge Sorted Array) идём **с конца**, чтобы не затирать непрочитанное.

```python
def is_subsequence(s: str, t: str) -> bool:
    i = 0
    for ch in t:
        if i < len(s) and s[i] == ch:
            i += 1
    return i == len(s)
```

**Типовые задачи:** Merge Sorted Array, Is Subsequence, Intersection of Two Arrays II, Backspace String Compare.

Сложность: $O(n + m)$ по времени, $O(1)$ по памяти.
