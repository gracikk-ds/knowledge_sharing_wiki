В [[dp-1d]] состояние описывалось одним индексом — «сколько префикса обработано». Здесь индексов два: позиции в **двух строках** (сравниваем последовательности), **клетка сетки** $(i, j)$ (grid DP), **границы интервала** $[l, r]$ (interval DP) или пара «позиция + ресурс» (knapsack). Сам рецепт не меняется: формулируем $dp[i][j]$ словами, выписываем переход, следим за порядком заполнения — каждая клетка должна опираться только на уже посчитанные. Ниже — по разделу на каждое семейство; у каждого свой характерный сигнал в условии, по нему и распознаём.

## Grid DP: пути по сетке

**Сигнал.** Робот идёт из угла в угол, ходы только **вправо/вниз**; посчитать число путей или минимальную стоимость. Если ходить можно во все 4 стороны — это уже не DP, а BFS/Dijkstra на [[graphs]] / [[advanced-graphs]]: при произвольных ходах порядок заполнения таблицы ломается.

**Состояние и переход.** $dp[i][j]$ — ответ для клетки $(i, j)$: в неё приходим либо сверху, либо слева.

$$
dp[i][j] = \text{grid}[i][j] + \min(dp[i-1][j],\ dp[i][j-1])
$$

Для подсчёта путей (Unique Paths) $\min$ заменяется на сумму. Переход смотрит только на текущую и предыдущую строку, поэтому таблица сжимается до одной строки: $dp[j]$ до присваивания — «клетка сверху», $dp[j-1]$ — «клетка слева».

```python
def min_path_sum(grid: list[list[int]]) -> int:
    m = len(grid[0])
    dp = [float("inf")] * (m + 1)
    dp[1] = 0  # virtual cell above the start
    for row in grid:
        for j, x in enumerate(row, start=1):
            dp[j] = min(dp[j], dp[j - 1]) + x
    return dp[m]
```

**Типовые задачи:** Unique Paths, Unique Paths II, Minimum Path Sum, Maximal Square.

Сложность: $O(nm)$ по времени, $O(m)$ по памяти после сжатия.

## DP по двум последовательностям

**Сигнал.** Две строки/массива, спрашивают про общую подпоследовательность, минимум операций превращения одной в другую, «похожесть».

**Состояние и переход.** $dp[i][j]$ — ответ для префиксов $s[{:}i]$ и $t[{:}j]$; таблица $(n+1) \times (m+1)$, нулевая строка/столбец — пустой префикс. Для Longest Common Subsequence:

$$
dp[i][j] =
\begin{cases}
dp[i-1][j-1] + 1, & s_i = t_j \\
\max(dp[i-1][j],\ dp[i][j-1]), & s_i \neq t_j
\end{cases}
$$

Совпали символы — берём оба и удлиняем LCS; не совпали — выкидываем последний символ одной из строк, берём лучшее. Edit Distance — та же таблица, но переход перебирает **три операции**: замена ($dp[i-1][j-1]$), удаление ($dp[i-1][j]$), вставка ($dp[i][j-1]$), каждая стоит $1$; при $s_i = t_j$ бесплатно берём $dp[i-1][j-1]$.

```python
def lcs(s: str, t: str) -> int:
    n, m = len(s), len(t)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s[i - 1] == t[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[n][m]
```

**Типовые задачи:** Longest Common Subsequence, Edit Distance, Interleaving String, Delete Operation for Two Strings.

Сложность: $O(nm)$ по времени, $O(m)$ по памяти при хранении двух строк.

## Knapsack: 0/1 и unbounded

**Сигнал.** Набор предметов/чисел, каждый берём **или нет** (0/1) либо **сколько угодно раз** (unbounded), и есть ограничение-«ёмкость»: сумма, вес, количество. Полный перебор подмножеств — это [[backtracking]] за $O(2^n)$; DP схлопывает его, потому что важна не история выбора, а пара (сколько предметов рассмотрели, сколько ёмкости набрали).

**Состояние и переход.** $dp[i][c]$ — число способов (или лучший ответ) набрать сумму $c$ из первых $i$ предметов. Разница между вариантами — один индекс в переходе:

$$
\begin{aligned}
\text{0/1:} \quad dp[i][c] &= dp[i-1][c] + dp[\textcolor{blue}{i-1}][c - x_i] \\
\text{unbounded:} \quad dp[i][c] &= dp[i-1][c] + dp[\textcolor{blue}{i}][c - x_i]
\end{aligned}
$$

В 0/1 после взятия предмета ссылаемся на строку $i-1$ — второй раз его не взять; в unbounded — на строку $i$, предмет доступен снова. Target Sum сводится к 0/1: если $P$ — сумма чисел со знаком «плюс», а $S$ — общая сумма, то $P - (S - P) = \text{target}$, откуда $P = (S + \text{target})/2$ — считаем подмножества с такой суммой.

```python
def find_target_sum_ways(nums: list[int], target: int) -> int:
    s = sum(nums)
    if (s + target) % 2 or abs(target) > s:
        return 0
    goal = (s + target) // 2
    dp = [0] * (goal + 1)
    dp[0] = 1
    for x in nums:
        for c in range(goal, x - 1, -1):  # reverse: each item used once
            dp[c] += dp[c - x]
    return dp[goal]
```

В сжатом до одной строки виде различие превращается в **направление внутреннего цикла**: справа налево — 0/1 (клетка $dp[c-x]$ ещё «из прошлой строки»), слева направо — unbounded (уже «из текущей», предмет переиспользуется). В Coin Change II внешний цикл по монетам даёт **комбинации**: монета входит в переход только после того, как все способы без неё досчитаны, поэтому порядок монет внутри способа зафиксирован. Поменять циклы местами (внешний по сумме) — получим **перестановки**, это уже Combination Sum IV из [[dp-1d]].

```python
def change(amount: int, coins: list[int]) -> int:
    dp = [0] * (amount + 1)
    dp[0] = 1
    for coin in coins:                     # coins outer -> combinations
        for a in range(coin, amount + 1):  # forward: unlimited reuse
            dp[a] += dp[a - coin]
    return dp[amount]
```

**Типовые задачи:** Partition Equal Subset Sum, Target Sum (0/1); Coin Change II, Coin Change (unbounded).

Сложность: $O(n \cdot C)$ по времени, $O(C)$ по памяти, где $C$ — ёмкость.

## State machine DP

**Сигнал.** На каждом шаге мы находимся в одном из **малого числа режимов** (держим акцию / только что продали / отдыхаем), и переходы между режимами ограничены правилами. Вместо второго индекса-числа — второй индекс-состояние.

**Состояние и переход.** $dp[t][s]$ — лучшая прибыль к дню $t$ в состоянии $s$. Для Best Time to Buy and Sell Stock with Cooldown состояния: hold (держим акцию), sold (продали сегодня), rest (свободны, можно покупать):

$$
\begin{aligned}
\text{hold}_t &= \max(\text{hold}_{t-1},\ \text{rest}_{t-1} - p_t) \\
\text{sold}_t &= \text{hold}_{t-1} + p_t \\
\text{rest}_t &= \max(\text{rest}_{t-1},\ \text{sold}_{t-1})
\end{aligned}
$$

Cooldown зашит в структуру графа состояний: купить можно только из rest, а из sold в rest попадаем лишь на следующий день. Таблица по дням не нужна — храним три числа. Версии задачи без ограничений решаются жадно ([[greedy]]), state machine нужна, когда появляются cooldown, комиссия или лимит сделок (там добавляется индекс $k$).

```python
def max_profit(prices: list[int]) -> int:
    hold, sold, rest = float("-inf"), 0, 0
    for p in prices:
        hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)
```

**Типовые задачи:** Best Time to Buy and Sell Stock with Cooldown, ...with Transaction Fee, ...III/IV (лимит сделок), Paint House.

Сложность: $O(n \cdot |S|)$ по времени, $O(|S|)$ по памяти.

## Interval DP

**Сигнал.** Ответ для отрезка собирается из ответов для **вложенных** отрезков; операция «схлопывает» элементы, и стоимость зависит от того, что осталось по краям. Классический трюк Burst Balloons: думать не «какой шар лопнет первым» (после этого соседи меняются, подзадачи не независимы), а «какой лопнет **последним**» — тогда края $l$ и $r$ гарантированно живы, и левая/правая части не влияют друг на друга.

**Состояние и переход.** $dp[l][r]$ — лучший ответ для открытого интервала $(l, r)$; $k$ — шар, лопающийся последним:

$$
dp[l][r] = \max_{l < k < r}\bigl(dp[l][k] + a_l \cdot a_k \cdot a_r + dp[k][r]\bigr)
$$

Заполняем интервалы **в порядке роста длины** — переход ссылается только на строго более короткие. Это второй, после «строка за строкой», законный порядок обхода 2D-таблицы.

```python
def max_coins(nums: list[int]) -> int:
    a = [1] + nums + [1]
    n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):
        for l in range(n - length):
            r = l + length
            for k in range(l + 1, r):  # k bursts last within (l, r)
                dp[l][r] = max(dp[l][r], dp[l][k] + a[l] * a[k] * a[r] + dp[k][r])
    return dp[0][n - 1]
```

**Типовые задачи:** Burst Balloons, Minimum Cost to Cut a Stick, Matrix Chain Multiplication, Stone Game (варианты).

Сложность: $O(n^3)$ по времени, $O(n^2)$ по памяти — сжать не выйдет, нужны все длины интервалов.

## Палиндромные подпоследовательности

**Сигнал.** Одна строка, но состояние — **два её конца**: палиндром определяется парой «первый символ, последний символ». Родственник interval DP, только переход дешёвый — без перебора точки разреза.

**Состояние и переход.** $dp[i][j]$ — длина самой длинной палиндромной подпоследовательности в $s[i{:}j]$:

$$
dp[i][j] =
\begin{cases}
dp[i+1][j-1] + 2, & s_i = s_j \\
\max(dp[i+1][j],\ dp[i][j-1]), & s_i \neq s_j
\end{cases}
$$

Красивая связь с предыдущими паттернами: LPS строки $s$ — это в точности LCS пары $(s, \text{reverse}(s))$, так что задача решается и таблицей из раздела про две последовательности. Прямой вариант ниже заполняется по $i$ снизу вверх — те же «интервалы растущей длины», записанные иначе.

```python
def longest_palindrome_subseq(s: str) -> int:
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1]
```

**Типовые задачи:** Longest Palindromic Subsequence, Palindromic Substrings, Longest Palindromic Substring (там substring — таблица булева).

Сложность: $O(n^2)$ по времени и памяти.

## Матчинг с шаблоном

**Сигнал.** Строка против шаблона со спецсимволами (`.`, `*`, `?`) или подсчёт способов «вложить» одну строку в другую. Таблица как в LCS, но переходы диктуются семантикой символа шаблона.

**Состояние и переход.** $dp[i][j]$ — матчится ли $s[{:}i]$ с $p[{:}j]$. Вся сложность Regular Expression Matching — в `*`, который значит «ноль или больше копий предыдущего символа»:

$$
dp[i][j] =
\begin{cases}
dp[i-1][j-1], & p_j \in \{s_i,\ \texttt{.}\} \\
dp[i][j-2] \ \lor\ \bigl(p_{j-1} \in \{s_i,\ \texttt{.}\}\ \land\ dp[i-1][j]\bigr), & p_j = \texttt{*}
\end{cases}
$$

Первая ветка для `*` — выкинули пару «символ + звёздочка» (ноль копий), вторая — съели $s_i$ ещё одной копией и остались на том же $j$. Базовый случай тоже нетривиален: пустая строка матчится с шаблонами вида `a*b*`. Distinct Subsequences — та же таблица, но считаем **число** способов: при $s_i = t_j$ складываем «использовали $s_i$» и «пропустили $s_i$».

```python
def is_match(s: str, p: str) -> bool:
    n, m = len(s), len(p)
    dp = [[False] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = True
    for j in range(2, m + 1):
        dp[0][j] = p[j - 1] == "*" and dp[0][j - 2]  # a*b* matches ""
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if p[j - 1] == "*":
                dp[i][j] = dp[i][j - 2]  # zero copies
                if p[j - 2] in (s[i - 1], "."):
                    dp[i][j] |= dp[i - 1][j]  # one more copy
            elif p[j - 1] in (s[i - 1], "."):
                dp[i][j] = dp[i - 1][j - 1]
    return dp[n][m]
```

**Типовые задачи:** Regular Expression Matching, Wildcard Matching, Distinct Subsequences.

Сложность: $O(nm)$ по времени и памяти.

## Оптимизация памяти

Общее правило: если переход из $dp[i][\cdot]$ смотрит только на строки $i-1$ и $i$, таблица сжимается до одной-двух строк — так устроены grid DP, две последовательности, knapsack и матчинг. Память падает с $O(nm)$ до $O(m)$, время не меняется. Цена — **порядок обхода становится содержательным**: в одной строке клетка $dp[j]$ до перезаписи играет роль «прошлой строки», после — «текущей», и направление внутреннего цикла решает, какую из версий мы читаем. Отсюда правило knapsack: справа налево — предмет берётся один раз (0/1), слева направо — переиспользуется (unbounded); перепутать направление — самый тихий баг раздела, тесты на маленьких входах его часто не ловят. Не сжимаются interval DP и палиндромы: там переход тянется к интервалам всех меньших длин, а не к соседней строке. И последнее: если нужно восстановить сам ответ (путь, подпоследовательность), а не только его стоимость, полную таблицу обычно приходится оставить — по сжатой строке путь назад не раскрутить.

## Карта раздела

| Паттерн | Состояние $dp[i][j]$ | Типовая задача | Сложность |
|---|---|---|---|
| Grid DP | клетка $(i, j)$ сетки | Minimum Path Sum | $O(nm)$ |
| Две последовательности | префиксы $s[{:}i]$, $t[{:}j]$ | Longest Common Subsequence, Edit Distance | $O(nm)$ |
| 0/1 knapsack | первые $i$ предметов, ёмкость $j$ | Target Sum, Partition Equal Subset Sum | $O(nC)$ |
| Unbounded knapsack | монеты до $i$-й, сумма $j$ | Coin Change II | $O(nC)$ |
| State machine | день $i$, режим $j$ | Stock with Cooldown | $O(n \cdot \lvert S \rvert)$ |
| Interval DP | интервал $(i, j)$ | Burst Balloons | $O(n^3)$ |
| Палиндромы | подстрока $s[i{:}j]$ | Longest Palindromic Subsequence | $O(n^2)$ |
| Матчинг с шаблоном | префиксы строки и шаблона | Regular Expression Matching | $O(nm)$ |
