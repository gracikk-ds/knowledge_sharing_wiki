# onboard

Цель — провести нового человека от «открыл репо первый раз» до «сделал первый разбор и опубликовал». Скилл идёт по 7 коротким фазам, каждая стопится на подтверждении пользователя.

**Важно:** это интерактивный гид, а не информационный дамп. Не пиши все 7 фаз одним сообщением. Иди по одной фазе за раз, дождись ответа, потом переходи к следующей. Используй TodoWrite, чтобы пользователь видел прогресс.

## Pre-flight

- [ ] Создай TodoWrite с 7 пунктами — по одному на фазу.
- [ ] Прочитай `.claude/CLAUDE.md` (контекст про репо).
- [ ] Прочитай `wiki/index.md` (что уже разобрано).
- [ ] Глянь `ls raw/` (что лежит в исходниках).

---

## Фаза 1 — Что это такое (1 минута)

Напиши пользователю:

```
Привет 👋 Это личный LLM-поддерживаемый wiki по ML.

Идея простая: ты складываешь papers, лекции, статьи и записи KS в `raw/`,
Claude через скилл `/wiki-ingest` разбирает их по единому шаблону, и со
временем у тебя — сеть связанных страниц по тегам, по которой быстро
находишь нужное.

За 5-10 минут пройдём весь цикл: посмотрим что лежит в репо, какие
команды доступны, и (если есть желание) сделаем твой первый разбор.

Готов? Скажи «да» или «продолжаем», и пойдём дальше.
```

Дождись ответа. Если пользователь отказался — закрывай скилл вежливо. Если согласился — отметь фазу 1 как completed и иди к фазе 2.

## Фаза 2 — Layout репо (1 минута)

Напиши:

```
Структура репо:

  raw/                # сюда кладёшь исходники (read-only после коммита)
    papers/  lectures/  clips/  knowledge-sharings/  scratch/
  wiki/               # сюда Claude пишет разборы
    papers/  lectures/  clips/  knowledge-sharings/
    static/figures/   # все картинки одной плоской папкой
    index.md          # лендинг + Recent / by-kind / by-tag
    tags.md           # реестр тегов с определениями
    log.md            # хронологический журнал ingest/lint
  publish/            # Quartz, деплоится на Vercel из main
  .claude/            # инструкции, правила, агенты, скиллы
    CLAUDE.md  role.md  rules/  agents/  skills/

Правило простое:
  raw/   — твоё, Claude только читает
  wiki/  — Claude пишет, ты ревьюишь и коммитишь
  .claude/ — конфигурация, читай свободно

Ок? Идём дальше.
```

Дождись ответа.

## Фаза 3 — Что уже есть в raw/ (1 минута)

Выполни `ls -la raw/papers/ raw/clips/ raw/lectures/ raw/knowledge-sharings/ 2>/dev/null` и покажи пользователю список текущих исходников. Если пусто — скажи прямо.

Затем выполни `ls wiki/papers/ wiki/lectures/ wiki/clips/ wiki/knowledge-sharings/ 2>/dev/null | grep -v gitkeep` и покажи список уже разобранных.

Сделай вывод: «вот это уже разобрано / вот это ждёт разбора».

```
Чтобы добавить новый источник — просто положи файл в нужную подпапку
raw/. PDF → raw/papers/, видео-лекция или markdown с расшифровкой →
raw/lectures/, статья из блога → raw/clips/, запись внутреннего KS →
raw/knowledge-sharings/. Имя файла любое.

Готов посмотреть какие команды доступны?
```

Дождись ответа.

## Фаза 4 — Команды (2 минуты)

Напиши:

```
Все основные операции — через скиллы (slash-команды):

  /wiki-ingest raw/<path>  — главный флоу: разобрать один источник
                             в одну страницу. Проходит 9 фаз (читает
                             исходник, извлекает картинки, опционально
                             исследует пробел, согласует план с тобой,
                             пишет страницу, делает картинки, проверяет
                             стиль, обновляет index/tags/log).

  /wiki-query "<вопрос>"   — ответить на вопрос по wiki: найти
                             разборы по тегам, синтезировать ответ
                             с цитатами.

  /wiki-lint               — аудит wiki: orphan-страницы, битые ссылки,
                             ошибки frontmatter, неконсистентные теги.

  /wiki-quiz <тема>        — сгенерить тест по теме для самопроверки.

  /autodoc                 — записать сессионные инсайты в .autodoc/.

  /onboard                 — этот гид (уже бежит).

Подробности по каждому скиллу — в .claude/skills/<skill>/SKILL.md.

Ок? Идём к практике.
```

Дождись ответа.

## Фаза 5 — Первый разбор (опционально, 5-15 минут)

Спроси:

```
Хочешь прямо сейчас сделать первый разбор? Варианта три:

  (a) У тебя есть конкретный файл, который хочешь разобрать —
      положи его в raw/<нужная подпапка>/ и скажи путь, я запущу
      /wiki-ingest на нём.

  (b) Возьмём что-то из уже лежащего в raw/. Скажи "возьми X"
      и я запущу /wiki-ingest на нём.

  (c) Пропустить шаг — пройдём оставшиеся фазы (commit/push, поиск
      по wiki) без живого разбора.

Что выбираешь?
```

Дождись ответа:
- Если (a) или (b): дай знать пользователю что запускаешь `/wiki-ingest`, передавай управление скиллу wiki-ingest. После завершения вернись в onboard и переходи к фазе 6.
- Если (c): отметь фазу 5 как пропущенную и переходи к фазе 6.

## Фаза 6 — Commit и push (2 минуты)

Напиши:

```
Когда разбор готов, остаётся два шага.

(1) Коммит. /wiki-ingest на последней фазе предложит тебе сообщение
коммита по шаблону:

    feat(wiki): ingest <source> — <short-desc>

    - new: wiki/<kind>/<slug>.md
    - update: wiki/index.md
    - update: wiki/log.md
    - figures: wiki/static/figures/<slug>-<name>.png
    - update: wiki/tags.md  (если добавили новый тег)

Ты подтверждаешь — Claude делает `git commit`. Правило репо: один
коммит ≤ 300 строк. Если разбор большой — Claude сам разделит на
несколько атомарных коммитов.

(2) Push. Claude может пушить сам — без отдельного апрува. Перед push
в `main` он прогонит /wiki-lint и поправит блокеры (битые ссылки,
frontmatter, теги вне реестра). Force-push и пуш в `main` из feature-
ветки всё ещё требуют твоего явного OK.

    git push origin main

Vercel автоматически деплоит main → ml-notes-wiki.vercel.app.

Ок? Последняя фаза — где документация.
```

Дождись ответа.

## Фаза 7 — Где искать дальше (1 минута)

Напиши:

```
Финиш. Если нужно глубже:

  README.md                       — обзор репо
  .claude/CLAUDE.md               — главные инструкции для Claude и
                                     описание шаблонов
  .claude/role.md                 — роль и стиль
  .claude/rules/01-language-policy.md  — язык, как писать
  .claude/rules/02-commit-policy.md    — коммит-формат
  .claude/rules/03-illustration-policy.md  — иллюстрации
  .claude/rules/04-frontmatter-schema.md   — frontmatter
  .claude/skills/_shared/page-templates.md  — шаблон страниц
  .claude/skills/_shared/russian-style.md   — стиль русской прозы

  wiki/index.md       — навигация по всем разборам
  wiki/tags.md        — реестр тегов с определениями
  ONBOARDING.md       — текстовая версия этого гида

Удачи!
```

Отметь фазу 7 completed. Скилл завершён.

## Когда onboard НЕ запускать

- Пользователь уже опытен — он сам спрашивает что-то конкретное по wiki (`/wiki-query`, `/wiki-ingest`). Не врубай гид без явного запроса.
- Если пользователь явно сказал «я уже знаю» в начале — закрывай скилл сразу.

## Если пользователь хочет вернуться к гиду позже

`/onboard` можно запустить заново в любой момент. Каждый запуск — независимый, без сохранения прогресса между сессиями.
