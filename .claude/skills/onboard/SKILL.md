# onboard

Цель — провести нового человека от «открыл репо первый раз» до «сделал первый разбор и опубликовал».

**Главное правило:** ничего не утверждай о репо, пока не посмотрел его глазами. Структура папок, набор скиллов, что лежит в `raw/`, что уже разобрано — всё это меняется. Каждую фазу начинай с `ls` / `git` / `cat`, и говори пользователю про **реальное** состояние, а не про шаблон.

**Темп:** одна фаза за сообщение. Дождись ответа («да», «понял», «дальше», «вопрос: …»), потом следующая. TodoWrite с 7 пунктами держит прогресс на виду.

## Pre-flight

- [ ] Создай TodoWrite с 7 пунктами — по одному на фазу.
- [ ] Прочитай `.claude/CLAUDE.md` (контекст про репо).
- [ ] Прочитай `wiki/index.md` если он существует (что уже разобрано).

## Фаза 1 — Что это такое (1 минута)

Напиши пользователю одну короткую вводную:

```
Привет 👋 Это личный LLM-поддерживаемый wiki по ML.

Идея простая: ты складываешь исходники (papers, лекции, статьи,
записи KS) в `raw/`, Claude через скилл /wiki-ingest разбирает их
по единому шаблону, и со временем — сеть связанных страниц по тегам,
по которой быстро находишь нужное. Сайт собирается Quartz, деплоится
на Vercel из main.

За 5-10 минут пройдём весь цикл: посмотрим что в репо сейчас, какие
команды доступны, и (если хочешь) сделаем твой первый разбор.

Готов?
```

Дождись «да». Если отказался — закрывай вежливо. Если согласился — отметь фазу 1 как completed.

## Фаза 2 — Что в репо сейчас (2 минуты)

**Не рисуй ascii-диаграмму. Покажи живые ls и расскажи.**

Запусти:

```bash
ls -1 .
ls -1 raw/ 2>/dev/null
ls -1 wiki/ 2>/dev/null
```

Сформулируй вывод в 2-3 фразы, опираясь на то, что увидел. Пример:

```
Сейчас вижу:
- raw/ — твои исходники: <перечисли реальные подпапки>. Пишешь сюда,
  Claude читает; в git эта папка не коммитится (только структура
  подпапок через .gitkeep).
- wiki/ — куда Claude пишет разборы: <перечисли реальные подпапки и
  файлы tags.md / log.md / index.md если они есть>.
- publish/ — Quartz, деплоится на Vercel из main.
- .claude/ — инструкции, правила, скиллы.

Готов посмотреть, что уже разобрано?
```

Дождись ответа.

## Фаза 3 — Что уже разобрано (1 минута)

Запусти:

```bash
find wiki/papers wiki/lectures wiki/clips wiki/knowledge-sharings -name '*.md' 2>/dev/null | sort
ls raw/papers raw/lectures raw/clips raw/knowledge-sharings 2>/dev/null
```

Расскажи реальное состояние:
- Сколько страниц уже есть, по каким источникам, какие теги.
- Что лежит в `raw/` и ещё не разобрано (если что-то лежит).
- Если репо пустой — скажи прямо «пока чисто, начнём с твоего первого источника».

Закончи переходом:

```
Чтобы добавить новый источник — просто положи файл в нужную подпапку
raw/. PDF → raw/papers/, видео-лекция или markdown с расшифровкой →
raw/lectures/, статья из блога → raw/clips/, запись внутреннего KS →
raw/knowledge-sharings/. Имя файла любое.

Готов посмотреть какие команды доступны?
```

Дождись ответа.

## Фаза 4 — Команды (2 минуты)

**Не зашивай список скиллов. Получи его с диска.**

Запусти:

```bash
ls -1 .claude/skills/ | grep -v '^_'
```

Для каждого реально существующего скилла прочитай первую строку `description:` из его SKILL.md:

```bash
for skill in $(ls .claude/skills/ | grep -v '^_'); do
  desc=$(awk '/^description:/{sub(/^description: */, ""); print; exit}' ".claude/skills/$skill/SKILL.md")
  printf '/%s — %s\n' "$skill" "${desc:0:120}"
done
```

Покажи пользователю получившийся список с короткими описаниями. Не выдумывай скиллы — если на диске их нет, в гиде их нет.

В конце добавь:

```
Подробности по каждому скиллу — в .claude/skills/<skill>/SKILL.md.

Ок? Идём к практике.
```

Дождись ответа.

## Фаза 5 — Первый разбор (опционально, 5-15 минут)

Спроси:

```
Хочешь прямо сейчас сделать первый разбор? Варианта три:

  (a) У тебя есть конкретный файл, который хочешь разобрать —
      положи его в raw/<нужная подпапка>/ и скажи путь, я запущу
      /wiki-ingest на нём.

  (b) Возьмём что-то из уже лежащего в raw/. Скажи "возьми X"
      и я запущу /wiki-ingest на нём.

  (c) Пропустить шаг — пройдём оставшиеся фазы (commit/push, хуки,
      где смотреть документацию) без живого разбора.

Что выбираешь?
```

Дождись ответа:
- Если (a) или (b): запусти `/wiki-ingest <путь>`, передавай управление. После завершения вернись в onboard.
- Если (c): отметь фазу 5 как пропущенную и иди дальше.

## Фаза 6 — Commit, hooks, push (3 минуты)

Напиши:

```
Когда разбор готов, остаётся три шага.

(1) Хуки. Один раз поставь:

    bash .githooks/install.sh

Это включит локальные git-хуки (.githooks/):
  - pre-commit — проверяет, что у каждой страницы wiki есть
    frontmatter; предупреждает, если коммит больше 300 строк.
  - pre-push — на каждый push, на любой ветке: считает содержательные
    коммиты с последнего chore(autodoc):. Если их ≥ 2, напомнит
    запустить /autodoc, чтобы не терять выводы сессии. На
    «push anyway? [y/N]» можно ответить y и пушить без autodoc.
    Работа часто живёт на feature-ветках — autodoc-гард там же.

(2) Коммит. /wiki-ingest на последней фазе предложит сообщение по
шаблону:

    feat(wiki): ingest <source> — <short-desc>

    - new: wiki/<kind>/<slug>.md
    - update: wiki/index.md
    - update: wiki/log.md
    - figures: wiki/static/figures/<slug>-<name>.png
    - update: wiki/tags.md  (если добавили новый тег)

Подтверждаешь — Claude делает git commit. Правило: один коммит
≤ 300 строк. Большие разборы Claude сам разделит на атомарные коммиты.

(3) Push. Claude может пушить сам, без отдельного апрува. На любой
ветке хук pre-push сработает на этом шаге — если в ветке накопилось
≥ 2 содержательных коммита без autodoc, он остановит и предложит
запустить /autodoc. Перед push в main Claude дополнительно прогонит
/wiki-lint и поправит блокеры. Force-push и пуш в main из feature-
ветки всё ещё требуют твоего явного «ок».

    git push origin main

Vercel задеплоит main → ml-notes-wiki.vercel.app.

Если за сессию правил .claude/role.md, .claude/rules/ или
.claude/skills/*/SKILL.md — это идёт через /skill-updater, не
hand-edit. Он активируется когда ты прямо просишь («обнови скиллы»,
«учти инсайты»), или когда в .autodoc/insights.md накопится ≥ 5
новых записей. Claude кладёт diff в .claude/proposed-changes/<дата>.diff,
ты говоришь «apply hunks 1, 3, 5» — только после этого правки
применяются.

Ок? Последняя фаза — где документация.
```

Дождись ответа.

## Фаза 7 — Где искать дальше (1 минута)

Покажи реальные файлы, которые есть на диске. Запусти:

```bash
ls .claude/rules/
ls .claude/skills/_shared/ 2>/dev/null
test -f wiki/index.md && echo "wiki/index.md есть"
test -f wiki/tags.md && echo "wiki/tags.md есть"
```

Сформулируй короткий список по живому состоянию. Пример:

```
Финиш. Если нужно глубже:

  README.md                          — обзор репо
  .claude/CLAUDE.md                  — главные инструкции для Claude
  .claude/role.md                    — роль и стиль
  .claude/rules/<реальные файлы>     — правила (язык, коммиты, картинки, frontmatter)
  .claude/skills/_shared/<…>         — шаблоны страниц и стиль прозы
  wiki/index.md                      — навигация по разборам
  wiki/tags.md                       — реестр тегов

Запускай /wiki-ingest на любом источнике, когда будет первый файл
в raw/. Если что-то непонятно — спроси в чате, либо запусти
/onboard ещё раз.

Готово 🚀
```

Отметь все 7 фаз как completed.

## Что делать НЕ надо

- **Не хардкодь layout.** Если структура поменялась (новая подпапка в `wiki/`, новый скилл) — твой гид соврёт. Всегда `ls` сначала, потом рассказывай.
- **Не выдумывай скиллы.** Список — из `ls .claude/skills/`, описания — из первой строки `description:` в каждом SKILL.md.
- **Не пиши все фазы одним сообщением.** Это интерактивный гид, не справочник.
- **Не вгрызайся в детали.** Каждая фаза — 1-3 минуты на чтение. Глубокие правила пользователь прочтёт сам по ссылке в фазе 7.
- **Не предлагай скиллы, которых нет.** Если на диске нет `.claude/skills/foo/`, не упоминай `/foo`.
